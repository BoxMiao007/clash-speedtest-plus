# 测速视图交互质量静态审查（qa/01-speedtest-view.md）

> 审查对象：`internal/gui/` 测速视图及相关状态机。
> 审查方式：只读静态审查（grep/read/glob），未运行 go build/test/vet。
> 依据：`docs/specs/0001-viva-gui.md` 第 6–8 节、ADR-0020/0021/0022/0023/0026/0029、Nielsen 十大原则、桌面平台设计惯例。
> 结论：发现 11 条（严重 1 / 一般 7 / 轻微 3），另列功能缺失 4 项、待确认 6 项。

## 一、合理的交互点（正面清单）

- **勾选与行选择分离做对了**：`node.selected`（复选框，决定测速/导出范围）与 `node.marked`（点行/Shift/Ctrl 的瞬时操作目标）完全解耦，点行不改勾选（`actions.go:1156`、`state.go:306-310`），符合 ADR-0029 决策 2。
- **修饰键左键在 pointer pass 处理并 Consume**（`view_speedtest.go:362-376`）：避开了 click pass 里 `canvas.pointer` 被清空导致拿不到修饰键/位置的问题，是平台正确的实现路径（ADR-0029 §6）。
- **Shift 范围替换语义 + 反向范围**（`actions.go:1204-1234`）：锚点在目标之后也能正确选中，范围外清除，符合文件管理器习惯。
- **固定组标题裁剪后命中收窄**（`view_speedtest.go:79-106`）：被 33px 标题盖住的行不绘制、不可点击，跨顶行只画下半截，避免覆盖可点区域造成 layout 重叠（ADR-0023 决策 3）。
- **详情弹窗推 layer 1 + 同层先矩形后文字**（`view_speedtest.go:451-486`）：解决「透明弹窗」根因；dismiss 同 pass 关闭后不再继续画，避免空指针。
- **排序文案/无障碍名预计算**（`view_speedtest.go:247-271`）：箭头、`sortHit*` 在状态变化时算好，绘制路径不拼串，贴合 0 分配约定。
- **排序只在组内 + 节点稳定身份**（`state.go:989-1091`）：按条目分组不混排，行 ID 来自节点身份，重排不变；`node.order` 兜底未测速读取顺序。
- **轮次账本与查看轮解耦**（`actions.go:596-611`）：完成/提前结束/推进只认 `runRound()`，迟到事件按 `event.round` 丢弃，符合 8.5「过期轮次事件丢弃」。

## 二、问题清单

### [ST-01] 多选右键「取消选中所选节点」点击后无任何效果
- **严重级别**：严重（核心功能异常）
- **类型**：功能缺陷 / 状态流转
- **位置**：`internal/gui/contextmenu.go:50-54`（生成菜单项）、`internal/gui/actions.go:169-205`（`activateMenu` 分发）
- **关键代码**：
  - `contextmenu.go:51-53`：`if allChecked { selectID, selectLabel = a.ids.menuUnselMulti, "取消选中所选节点" }`
  - `actions.go:185-190`：`case a.ids.menuSelect, a.ids.menuUnselect:` … **没有 `a.ids.menuUnselMulti`**
- **复现步骤**：
  1. 某分组全部节点默认已勾选；Shift 选中多行（或 Ctrl 多选 ≥2 行）形成 marked 多选语境；
  2. 右键其中一行 → 菜单显示「取消选中所选节点」；
  3. 点击该项：菜单关闭，但这几行的勾选状态完全不变。
  代码路径：点击 → `activateMenu(a.ids.menuUnselMulti)` → `switch` 中无匹配分支 → 落到函数末尾，没有任何状态修改。
- **期望 vs 实际**：期望把这些 marked 行的 `selected` 置 false（与文案一致）；实际无操作，用户以为已取消但测速范围未变。
- **依据**：规格 8.4「多选语境：…取消选中所选节点…」；Nielsen #1 系统状态可见、#2 系统与真实世界匹配。该 ID 在 `ids.go:134,260` 注册、只在 `contextmenu.go:52` 生成，全仓无消费点（grep 确认）。
- **置信度**：高（静态可直接确定漏分支）。

### [ST-02] 详情弹窗打开后，左键点击其它节点行既不关闭也不切换弹窗
- **严重级别**：一般（体验受损，且易误读数据）
- **类型**：交互逻辑 / 事件处理冲突
- **位置**：`internal/gui/view_speedtest.go:372-376`（行 pointer 处理 Consume）、`view_speedtest.go:431-445`（`paintDetailPopup` 全窗 dismiss）、`actions.go:1156-1169`（`handleRowClick` 不关详情）
- **关键代码**：
  - `view_speedtest.go:373-375`：`if event.Kind == PointerUp && Primary && ClickCount==1 { a.handleRowClick(...); canvas.Consume() }`
  - `view_speedtest.go:441-444`：dismiss 只在 `canvas.Clicked(a.ids.detailDismiss)`（click pass）触发
- **复现步骤**：
  1. 点某行行尾 `⋮` 打开详情（弹窗显示节点 A）；
  2. 左键单击另一节点行 B 的行体（弹窗之外）。
  事件顺序：行的 pointer pass 先 `handleRowClick(B)` 并 `Consume`，按 ADR-0029 §6「Consume 阻止重复的 click pass」，该次点击的 click pass 不再执行，`detailDismiss` 的 `Clicked` 不触发。
- **期望 vs 实际**：期望点弹窗外部（含其它行）关闭或切到该行详情；实际弹窗仍停在旧位置显示节点 A 的详情，同时 B 被标成 active/marked（两处高亮 + 旧弹窗内容），用户会误以为弹窗反映的是 B。
- **依据**：ADR-0029 决策 4「关闭途径：…点弹窗外任意处（全窗口 dismiss 命中，layer 0）」；Nielsen #1/#3 用户控制与自由、状态一致性。
- **置信度**：中高（代码路径明确；建议动态走查确认 Consume 与 Clicked 的先后，见待确认 T1）。

### [ST-03] 排序 / 测速结果刷新时，详情弹窗锚点固定，行会「跑掉」而弹窗停在旧位置
- **严重级别**：一般（体验受损，测速中尤其明显）
- **类型**：状态同步 / 交互逻辑
- **位置**：`internal/gui/state.go:234-245`（`setSort`）、`state.go:989-996`（`applySort`）、`view_speedtest.go:412-414`（`detailAnchor` 只在打开时取一次）
- **关键代码**：
  - `view_speedtest.go:414`：`a.detailAnchor = ui.Rect{X: x-12, Y: y-12, Width: 24, Height: 24}`
  - `setSort` / `applySort` 均未清空 `detailAnchor` 或关闭详情
- **复现步骤**：
  1. 打开某节点详情；
  2. 点表头「延迟」改为另一列排序；或直接在该节点测速中让结果/其它结果不断到达（`applyPending → applySort` 每帧重排）；
  3. 目标行随排序移动到别处，而弹窗仍画在打开时的屏幕坐标，和目标行脱节，甚至悬在别的行上方。
- **期望 vs 实际**：期望重排时关闭详情或让弹窗跟随目标行；实际弹窗浮在旧坐标，指向错误行。
- **依据**：ADR-0029 只承认「滚动后锚点不跟随、滚出视口即关闭」，未覆盖「同一视口内重排导致行位移」，属交互漏洞；Nielsen #1 状态可见、#2 匹配现实。
- **置信度**：中高（代码可证；外观需截图/走查确认）。

### [ST-04] 测速进行中仍可通过行复选框 / 组内全选 / 右键菜单修改勾选，与工具栏禁用口径矛盾
- **严重级别**：一般（一致性 / 潜在的测速范围误解）
- **类型**：状态流转 / 一致性
- **位置**：`view_speedtest.go:314-318`（行复选框 → `toggleNode` 无守卫）、`view_speedtest.go:663-668`（组标题全选/全不选无 `Disabled(a.running())`）、`contextmenu.go:185-200`（菜单选中/排除无运行判断）、`actions.go:68-78`（`toggleNode`/`setGroupSelected` 无 `running()` 判断）
- **关键代码**：`view_speedtest.go:134/137/141` 工具栏的「全选/全不选/排除上次失败」都 `Disabled(a.running())`，`actions.go:122-125` `setAllNodesSelected` 还明确拒绝「测速进行中，先停止再改勾选」；但行复选框、组内全选、右键「选中/排除」都没有同等保护。
- **复现步骤**：
  1. 点「下载速度」开始测速；
  2. 此时点某行复选框，或点组标题「全不选」，或右键单行选「排除此节点」；
  3. 勾选立即改变、`selectedCount` 变化；但本轮 `run.batch` 在开测时已固定，实际测速范围不变。
- **期望 vs 实际**：期望运行中统一禁止改勾选（与工具栏一致并提示）；实际部分入口可改，造成「我已经排除了它，怎么还在测」的错觉。
- **依据**：AGENTS「测速进行中…先停止再改勾选」；规格 8.5「同一时间只允许一轮…运行中禁用读取/重新获取/新建/删除」体现的运行期锁定一致性；Nielsen #4 一致性。
- **置信度**：高（代码可证）。

### [ST-05] 切换查看轮次后，进度文案「已完成 x/y」取自运行/最后一轮，与「第 N/M 轮」张冠李戴
- **严重级别**：一般（数据误导）
- **类型**：状态流转 / 文案
- **位置**：`state.go:1252-1290`（`refreshRunText`）、`actions.go:409-423`（`switchRound`）
- **关键代码**：前缀用 `s.roundIndex+1`（查看轮），而 `case s.run != nil && s.run.total > 0: fmt.Sprintf("%s已完成 %d/%d", …, s.run.done, s.run.total)` 用的是 `s.run`（运行轮或最后一轮），二者未对齐。
- **复现步骤**：
  1. 条目 A 有 3 个节点、条目 B 有 5 个节点，全部测完；
  2. 结果条停在最后一轮 B，显示「第 2/2 轮 · 已完成 5/5」；
  3. 点「上一轮」切到 A：显示「第 1/2 轮 · 已完成 5/5 · 本轮完成」——A 实际只有 3 个节点。
  另：测速中切到别的轮时，前缀跟着查看轮变，但 `在测` 数仍是运行轮，文案混用。
- **期望 vs 实际**：期望进度数字跟随当前查看轮（或明确标注「运行中：第 k 轮」）；实际同一行里轮号与计数来自不同轮。
- **依据**：规格 8.3 进度文案示例；Nielsen #1 系统状态可见、#2 匹配现实。
- **置信度**：高（代码可证）。

### [ST-06] 表头数值列与数据行整体错位约 28px（缺少行尾三点占位）
- **严重级别**：一般（可读性 / 对齐）
- **类型**：UI 布局 / 视觉
- **位置**：`view_speedtest.go:202-215`（表头）、`view_speedtest.go:340-361`（数据行，末尾 `⋮` 宽 20 + Gap 8）
- **关键代码**：
  - 数据行末尾：`f.Text("⋮")…Width(20)…`（`359`），行有 10 个子控件、9 个 Gap；
  - 表头只有 9 个子控件、8 个 Gap，且「上次测速」之后没有 20px 占位。
- **推导**：两容器总宽相同、节点名列均为 `Grow(1)`，行固定宽度比表头多出「三点 20px + 多一个 Gap 8px = 28px」，节点名列相应少 28px，故状态/延迟/抖动/丢包/下载/上传/上次测速所有数值列在数据行里整体比表头左移 28px（该差值经展开后与复选框实际宽度无关）。
- **复现步骤**：打开任意有节点的测速视图，肉眼对照「状态/延迟/…/上次测速」表头与下方数字列——数字列整体偏左，表头「上次测速」几乎落在行尾三点区域上方。
- **期望 vs 实际**：期望表头与数据列严格右对齐；实际固定偏差约 28px。
- **依据**：规格 8.2 表头/行列表格；桌面表格控件惯例；Nielsen #4 一致性与标准。
- **置信度**：高（布局算术恒等式；最终像素建议截图复核，见 T2）。

### [ST-07] 未测速节点的「丢包」列显示 0.0% 而非「—」，与其它未测列不一致
- **严重级别**：一般（数据误导）
- **类型**：显示逻辑 / 边界
- **位置**：`internal/gui/format.go:47-52`（`formatLoss`）、`state.go:1315`（`node.lossText = formatLoss(node.result.PacketLoss)` 无条件调用）
- **关键代码**：`formatLoss` 只把负值归零后 `fmt.Sprintf("%.1f%%", value)`，没有「无结果 → 破折号」分支；`result.PacketLoss` 零值 0 → 显示 `0.0%`。
- **复现步骤**：打开含未测速节点的列表（刚读取、未开测）。该行：延迟 `—`、抖动 `—`、下载 `—`、上次测速「未测试」，但丢包显示 `0.0%`。
- **期望 vs 实际**：期望未测速时丢包列显示 `—`；实际显示 `0.0%`，用户会读成「实测 0% 丢包」。对比 `formatSpeed` 注释「非正值显示破折号，避免把没测到写成 0」，口径应统一。
- **依据**：规格 8.2 行信息（未测试明确标注）；Nielsen #2 匹配现实。
- **置信度**：高（代码可证）。

### [ST-08] 详情弹窗正文没有行数上限/滚动，超长错误信息可能撑出窗口
- **严重级别**：一般（边界 / 可用性）
- **类型**：边界缺陷 / 内容布局
- **位置**：`view_speedtest.go:455-468`（高度按 `len(lines)` 直接算）、`view_speedtest.go:489-509`（`detailText` 拼接 `DownloadError/UploadError` 原文）
- **关键代码**：`height := 24 + titleHeight + float32(len(lines))*lineHeight`；随后只对 `y` 做钳制 `y = max(min(y, max(a.window.Height-height-8, 8)), 8)`，**高度本身不裁剪、无滚动、无最多行限制**。
- **复现步骤**：构造下载/上传错误的节点（如订阅节点下载报错且错误字符串很长，或错误信息含长 URL），点 `⋮` 打开详情 → 弹窗高度可超过窗口高度，超出窗口底部的文字不可见且无法滚动查看。
- **期望 vs 实际**：期望按 ADR 限制行数（最多 14 行）或对正文裁剪/滚动；实际高度无上限。
- **依据**：ADR-0029 决策 4「正文用 `canvas.WrapLines` 换行（最多 14 行）」——实现缺该上限；Nielsen #8 美观极简 / 边界健壮性。
- **置信度**：高（注释/ADR 与代码直接矛盾）。

### [ST-09] 全部条目都未勾选时，空态文案错误地说「当前条目还没有读取到节点」
- **严重级别**：轻微（文案 / 状态识别）
- **类型**：空态处理
- **位置**：`view_speedtest.go:38-40`（`len(nodeItems)==0` 早退）、`view_speedtest.go:672-697`（`paintNodeEmpty`）、`state.go:947-977`（`rebuild` 只在 `entry.selected` 后 `total++`）
- **关键代码**：`rebuild` 对未勾选条目 `continue`，其节点不计入 `total`；当所有条目都未勾选时 `groups` 为空 → `nodeItems` 为空 → 走 `paintNodeEmpty`，`a.totalCount == 0` 分支输出「当前条目还没有读取到节点。」
- **复现步骤**：左侧把每个条目的复选框都取消（条目隐藏），右侧列表区显示「当前条目还没有读取到节点。」，且下方「读取」按钮列表为空——但条目其实都已读取过、只是被隐藏。
- **期望 vs 实际**：期望提示「没有勾选任何条目 / 请勾选左侧条目」；实际误导为「没读到节点」。
- **依据**：规格 8.2 空态（无条目说明、未读取显示状态、过滤无匹配提示）；Nielsen #1/#6 识别而非回忆。
- **置信度**：高（代码可证）。

### [ST-10] 「全选/全不选」改到未勾选（隐藏）条目的节点，但「已选 x/共 y」与状态栏数字不含它们
- **严重级别**：轻微（计数口径不一致）
- **类型**：状态 / 文案
- **位置**：`actions.go:121-142`（遍历所有 `s.entries` 的节点）、`state.go:947-982`（计数只统计已勾选条目）
- **关键代码**：`setAllNodesSelected` 无条件遍历 `s.entries` 全部条目；`rebuild` 里 `if !entry.selected { continue }` 在 `total++` 之前。
- **复现步骤**：条目 A（5 节点）勾选、条目 B（3 节点）未勾选；点「全不选」→ 状态栏「已取消全部节点勾选（8 个）」，但工具条显示「已选 0 / 共 5」；随后重新勾选 B，B 的节点已全部被取消勾选。
- **期望 vs 实际**：期望计数口径与实际改动范围一致（AGENTS：与「已选 x/共 y」同口径）；实际状态栏数字（8）与工具条总数（5）不一致，用户无法核对。
- **依据**：AGENTS「工具条全选/全不选作用于所有条目的所有节点…与『已选 x/共 y』同口径」；Nielsen #1。
- **置信度**：中高。

### [ST-11] 多选判定用 `markedCount`（含被过滤隐藏的行），操作目标用 `markedNodes`（仅可见），过滤后菜单措辞与实际目标数不符
- **严重级别**：轻微（一致性 / 边界）
- **类型**：多选 + 过滤交互
- **位置**：`contextmenu.go:20-32`、`actions.go:1179-1199`、`state.go:999-1011`（`pruneTransientAnchors` 不清 `marked`）
- **关键代码**：`if node.marked && a.markedCount() > 1 { targets = a.markedNodes() }`；`markedCount` 遍历 `s.nodes`（全部），`markedNodes` 只遍历 `s.nodeItems`（可见）。
- **复现步骤**：Shift 标记 A-01/A-02/A-03 → 输入过滤只保留 A-01（另两行被隐藏，`marked` 未清）→ 右键 A-01：`markedCount()==3>1` 判为多选语境，但 `markedNodes()` 只返回 A-01；菜单用「所选节点」措辞却只作用于 1 个，隐藏行仍处于 marked，清空过滤后重现高亮。
- **期望 vs 实际**：期望过滤后多选目标与文案一致，或重建时清掉隐藏行的 marked；实际计数与目标集合脱节。
- **依据**：ADR-0029 决策 2（menu 操作目标为行选择）；Nielsen #4。
- **置信度**：中高。

## 三、功能缺失清单

1. **「取消选中所选节点」形同虚设**：入口/文案/ID 都在，但 `activateMenu` 未接分支（见 ST-01）。影响：多选场景无法一键取消勾选，只能逐行点复选框或右键「排除」。
2. **详情弹窗超长内容无滚动/无行数上限**（见 ST-08）。影响：错误信息很长的节点无法在弹窗内完整阅读，且可能撑出窗口。
3. **测速列表缺少键盘可达性**：行选择（Shift/Ctrl 范围）、勾选、打开详情目前只有鼠标路径（`PointerOn` / `Clicked`）；未见行级焦点、方向键/Space/Enter 处理（应用级快捷键只有全选/全不选/开测/Esc 关详情）。影响：键盘用户无法在节点表内操作，属无障碍缺口（见待确认 T4，需确认 Viva 是否提供行焦点）。
4. **`sortByName` 有枚举无入口**：`state.go:467-475` 定义了 `sortByName`，`compareRows` 也实现了按名比较，但表头「节点」列没有可点击排序入口（`view_speedtest.go:205` 只是普通 `Text`）。若预期支持按名称排序则缺失；若按规格 8.2「除节点与状态外都可点表头排序」则属死代码。影响：按名称排序能力不可达（见待确认 T5）。

## 四、待确认项

- **T1（对应 ST-02）**：Viva 的 `canvas.Consume()` 是否确实阻止同一 pointer 事件的 click pass，从而让全窗 `detailDismiss` 的 `Clicked` 不执行？ADR-0029 §6 有此表述，但需动态走查「开详情后点另一行」确认最终行为。
- **T2（对应 ST-06）**：表头与数据列的文件级推导为 28px 偏差；真实像素受字体度量与复选框实际宽度影响，建议截图或 `layout`/命中矩形复核。
- **T3**：Esc 键能否关闭右键菜单/各类对话框？`shortcuts.go:46` 仅在 `dialog == dialogNone && detailNode != nil` 时处理 Esc；关于对话框文案却写「Esc 关闭详情或对话框」。菜单（`contextmenu.go` 无 Esc 分支）与 `flex.Dialog` 是否自带 Esc 关闭需确认（该点与 task-2/3 交叠，仅提示）。

- **T6**：节点行复选框在双击时是否触发两次 `Clicked` 导致勾选来回抵消（`view_speedtest.go:314-318` 未做 ClickCount 过滤）；需动态确认，可能与 AGENTS「双击第二下忽略」只覆盖行而不覆盖复选框有关。
