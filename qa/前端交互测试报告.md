## 一、测试概况

### 1.1 对象与环境
- 单窗口桌面应用，两个视图：测速（条目管理 + 节点勾选 + 结果表 + 详情浮层 + 右键菜单）与设置（测速/阈值/输出/上传表单）。
- 全部持久化在 程序目录/data/（settings / entries / presets / results / subscriptions）。
- 需求基线：docs/specs/0001-viva-gui.md；交互决策见 docs/adr/（尤其 0019 / 0020 / 0029）。

### 1.2 方法与证据链（可复现）
1. 基线回归：go test ./... -count=1 —— 全部包通过（gui 1.985s）。
2. headless 真实交互：go build -tags vivahead . 后用 VIVA_HEADLESS=1 线协议驱动真实二进制；夹具节点指向 127.0.0.1:1（不联网、快速失败）。使用 click/rightclick/dblclick/type/key/keydown/keyup/resize/shot/texts/hits/layout/focus/waitfor 命令取证。
3. 7 组自定义探针（qa/probe1.sh … probe7.sh）+ 官方 scripts/headless-walkthrough.sh（PASS，layout ok 0 problems）。
4. 截图取证：qa/shots/*.png（shot 命令输出，2× 像素）。
5. 静态审查：3 名审查员分区只读审查 internal/gui，产出 qa/01-speedtest-view.md、qa/02-settings-dialogs.md、qa/03-crosscut.md。本报告高价值结论均由 Lead 独立复算/动态复现，并标注验证方式。

### 1.3 覆盖矩阵（对照测试清单六维度）
| 维度 | 结论 | 说明 |
|---|---|---|
| 一、页面加载与可访问性 | 基本通过，响应式有缺陷 | 启动 ok ready 1180x800 scale=2；首帧即就绪；无资源 404（无外部资源，系统字体）；layout 默认 0 problems。缩到 ≤900px 出现裁切/重叠（G3） |
| 二、交互逻辑合理性 | 存在多处缺陷 | 见严重 S1/S2/S4、一般 G1/G6/G8 等 |
| 三、交互设计合理性(UX) | 总体良好，个别文案/反馈问题 | 详情/右键/空态/危险确认设计清晰；清空结果确认按钮写作「删除」（G14）、设置错误不定位（G4）、多轮导出状态被覆盖（G9） |
| 四、功能完整性 | 主功能齐全，有若干「入口存在但无效/半成品」 | 多选「取消选中」无效（S1）、多轮导出账本残留（S2）、预览失效（S5）、纯键盘不可完成核心操作（G11） |

| 六、缺陷识别 | 发现 27 项（严重5/一般14/轻微8） | 详见第三节 |

### 1.4 结论摘要
主流程（读取→过滤→勾选→测速→结果表→自动导出→设置）可以走通且产物正确，基础质量较高（无崩溃、布局默认无告警、单测全绿）。但存在 5 个严重问题，集中在「入口失效、误触、状态账本不一致、模态隔离」，会在真实使用中造成功能不可用或数据/隐私风险。建议优先修复 S1–S5。

## 二、合理的交互点（正面清单）

1. 勾选与行选择分离：点行只改「行选择/详情目标」，不改测速勾选（actions.go:1153-1169）；探针 probe5/probe6 实测「点行不改变已选数」。符合 ADR-0029。
2. 过滤非法正则不崩溃：正则模式下输入 ( 时，过滤条下方内联红字「正则表达式无效：…」，列表保留上一个有效过滤结果（probe1 / p1-04-regex-error.png）。
3. 表单校验失败不写盘：设置页填非法测速服务器 not-a-url 保存 → 顶部与状态栏提示「测速服务器地址必须是 http(s) URL / 设置未保存」，未落盘（probe1 / p1-03）。空条目名 → 对话框内「名称不能为空」。
4. 特殊字符安全：过滤框输入 <script>alert(1)</script> 不崩溃、按关键词处理，显示「没有节点匹配当前过滤条件」引导（probe1）。
5. 空态/错误态齐全：无条目、条目未读取、过滤无匹配、读取失败（组标题红字「读取失败」）均有对应 UI。
6. 详情浮层视觉良好：行尾 ⋮ 打开，字段含类型/服务器/条目/延迟/抖动/丢包/下载/上传/上次测速/错误（p2-11-detail.png）。
7. 右键菜单语境清晰：单选/多选措辞区分，运行中测试项置灰（p2-12-contextmenu.png）。
8. 危险操作二次确认：删除条目/预设、清空结果均弹确认框。
9. 自动导出骨架正确、持久化正确：走查生成 mixed-port: 7890、节点选择/自动选择 两组与 MATCH 规则；settings/entries/presets/results 落盘正确。
10. 键盘 Tab 顺序可达：设置页/主视图 Tab 焦点有序移动（probe3 focus 序列），Esc 可关闭对话框（probe3）。
11. 结果表体验好：实时重排、组内排序、固定组标题、行尾三点详情、徽标展示协议与路径形态（p2-10-results.png）。

## 三、问题清单（存在问题的交互点及改进建议）

### 3.1 严重（核心功能异常）

#### S1. 多选右键「取消选中所选节点」点击后无任何效果
- 类型：交互逻辑 / 死控件
- 位置：contextmenu.go:50-54 生成 menuUnselMulti；contextmenu.go:170-205 activateMenu 的 switch 没有该 ID 分支（menuSelect/menuUnselect 有，menuUnselMulti 无）。
- 复现步骤：全部 3 个节点默认勾选 → keydown ctrl 点 HK-01、HK-02 形成多选 → 右键 HK-01 → 点击「取消选中所选节点」。已选数保持 3/3 不变，菜单关闭但勾选未变（probe4）。
- 期望 vs 实际：期望把 marked 行取消勾选；实际完全无操作。
- 依据：规格 8.4 多选菜单；Nielsen #1 系统状态可见、#2 匹配现实。
- 影响：多选无法一键取消勾选；相邻「排除所选节点」可达同效果，但该入口是明确的假按钮，误导用户。
- 证据：动态复现（probe4：已选 3/3 前后不变）+ 代码确认无 case。

#### S2. 删除/重读条目后轮次账本不清理，结果条与手动导出仍引用已删除条目的节点
- 类型：交互逻辑 / 数据一致性（含隐私风险）
- 位置：actions.go:998-1016（删除条目只删 entries，不动 s.rounds）；state.go:1140-1160（结果行按 rounds[nodes] 生成）；s.rounds 仅在 actions.go:202/243/274/301 赋值，删除/重读路径无裁剪。
- 复现步骤：测完 3 个节点（3/3 完成）→ 点条目卡片「删除」→ 确认。条目已消失、中央变「欢迎使用/还没有节点来源条目」，但顶部结果条仍显示「第 1/1 轮 · 已完成 3/3 · 本轮完成」，且「导出配置/结果图/结果表/清空结果」按钮仍在，导出会把已删除条目的节点配置写回 yaml（probe7）。
- 期望 vs 实际：期望删除/重读后裁剪 rounds/results 或复位账本；实际账本残留。
- 依据：规格 8.2「节点被删除时详情/固定行自动清空」的一致性；Nielsen #1/#4。
- 影响：结果与导出内容错误；可能把已删条目节点凭据写进产物（隐私）。
- 证据：动态复现（probe7）+ 代码确认。

#### S3. 模态对话框未隔离应用级快捷键：F1 覆盖当前确认框；Ctrl+Enter 在新建条目输入框内后台开测
- 类型：交互设计 / 模态语义
- 位置：shortcuts.go:32-49（onKey 不检查 a.dialog；F1→openAbout 直接 a.dialog=dialogAbout，dialogs.go:54）；shortcuts.go:8-27（Ctrl+A/R 无 dialog 守卫）。
- 复现步骤 A：点击条目「删除」打开「删除条目」确认框 → 按 F1 → 确认框被「关于与帮助」顶掉（probe7：确认框文本消失、出现 构建提交/快捷键）。
- 复现步骤 B：点「新建条目」→ 点「名称」输入 → 按 Ctrl+Enter → 对话框仍在，但状态栏变「开始测试 2 个节点」、结果条出现「第 1/1 轮 · 已完成 0/2 · 在测 2」（probe5）。
- 期望 vs 实际：期望模态期间全局快捷键被阻断或先关闭对话框；实际穿透，可能丢失未保存表单或误触发测速。
- 依据：Windows 桌面模态规范；Nielsen #3/#5；ADR-0028 未声明快捷键可穿透模态。
- 备注：输入框聚焦时 F1 被 Viva 文本系统吞掉（probe5 未替换条目对话框），与「确认框无输入时 F1 生效」不矛盾——说明隔离应显式做，而非依赖平台行为。
- 证据：动态复现 A/B。

#### S4. 快速双击「下载速度」→ 第二击命中同位「停止测速」，测速刚开始即被停止
- 类型：交互逻辑 / 重复点击健壮性
- 位置：view_speedtest.go:147-158 —— 运行态最右侧按钮为「停止测速」，空闲态最右侧为「下载速度」，两者右对齐同位。
- 复现步骤：点「下载速度」开始测速后立刻 dblclick「下载速度」。第一击开测，运行态渲染把同位按钮换成「停止测速」，第二击命中它 → 状态栏「已停止测速」、进度「已完成 0/3」（probe2）。
- 期望 vs 实际：期望重复点击被忽略或防抖；实际主操作被双击误停。
- 依据：清单「重复点击/快速连点不应产生异常」；Nielsen #5 错误预防。
- 影响：习惯性双击主按钮时静默中止测速，需重试。
- 证据：动态复现（probe2：3/3 → 双击后 0/3 + 已停止测速）。

#### S5. 开启「输出(非关闭)+结果图」时，测后「预览结果图」必然失效
- 类型：缺陷 / 路径聚合错误
- 位置：export.go:156 path = output.JoinStatus(path, imagePath)；output/resultimage.go:1209-1218 JoinStatus 以「；」拼接两段；actions.go:794-797 仅凭 .png 后缀把复合串写入 lastImage；消费方 view_speedtest.go:178-181。
- 复现步骤：设置「输出模式=当前目录下」（或自定义），保持「每轮自动保存结果图」开启（默认 image_enabled=true）→ 测一轮自动导出 → 点「预览结果图」→ os.Stat 失败，状态栏「结果图不存在」。
- 期望 vs 实际：期望预览本轮 PNG；实际 lastImage = 「…N.a-导出.yaml；…N.a-….png」，指向不存在的文件。默认输出=关闭时 path 为空、恰好正确，既有测试未覆盖。
- 依据：规格 8.7 + ADR-0028 第 7 条；Nielsen #1。
- 证据：代码确认（JoinStatus 实现 + 后缀判断 + 默认 image_enabled=true）；建议真机补一次预览复核。

## 四、功能缺失清单（缺失功能 + 影响范围）

| # | 缺失功能 | 影响范围 | 依据/说明 |
|---|---|---|---|
| 1 | 纯键盘完成核心操作：无法键盘打开详情、无法键盘滚动/访问视口外节点、行/⋮ 无键盘激活 | 仅键盘/辅助技术用户无法完成核心任务 | G11；WCAG 2.1.1/2.4.7 |
