# ADR-0021：条目路径/协议徽标、多选单独测试与详情留白修复

- 状态：已接受
- 日期：2026-10-30
- 关联：[ADR-0019](0019-interaction-polish.md)、[ADR-0020](0020-merged-test-view.md)、[规格 0001](../specs/0001-viva-gui.md)

## 背景

合并视图试用截图提出三处问题：

1. 条目卡片把同一个路径写了两遍（`硬路径 · D:\…\米贝.yaml` 与下一行 `D:\…\米贝.yaml`），并要求「保留一条路径，软/硬路径使用徽标表示」。
2. 行内协议类型（`Trojan` / `Vless` / `Shadowsocks`）夹在副标题里不醒目，要求「使用徽标突出显示」。
3. 多选后右键，菜单只有「立即测试所选节点」；希望「右键菜单添加当前指向的节点单独测试」。
4. 打开详情面板后，列表底部出现大片空白。

## 决策

1. **条目卡片只显示一条路径**：本地条目显示解析后的完整路径，形态用徽标 `软路径` / `硬路径` 表示；订阅条目显示 URL，徽标 `订阅`。不再保留「软路径 · xxx」前缀与第二行绝对路径。
2. **订阅缓存路径不再显示在卡片上**。缓存位置固定为 `data/subscriptions/<条目 ID>.yaml`，由 README 说明；卡片只保留 URL 与状态，少一行噪音。
3. **协议类型用徽标**：行副标题拆成 `server:port` + 类型徽标（`paintPill`），徽标用主题 `Muted` 底、圆角、字号 9；不再拼进副标题字符串。
4. **多选右键增加 `单独测试此节点`**：`menuState` 记录右键指向的节点；该菜单项只把指向节点交给引擎（单击右键菜单里已有 `立即测试此节点`，因此只在多选语境添加）。
5. **详情留白修复**：`nodeViewport` 是上一帧列表（Stack）的实际高度，已经扣掉详情面板；绘制时再减 `detailPanelHeight` 会让虚拟化阈值偏小，底部几行被跳过、露出空白。现在只在首帧没有记录时用窗口高度估算并扣减详情高度。
6. **中文徽标的宽度**：Viva 布局检查用的参考字宽把 CJK 按约 1.35em 估，平台排版按 1em，自动宽度的中文徽标会被判为截断。`paintPill` 对含非 ASCII 的标签设最小宽度 `1.45em × 字数 + 内边距`，两种度量都放得下；ASCII 协议名保持自动宽度。

## 取舍

- 订阅条目的缓存文件路径从界面消失，排查缓存问题时需要按 README 的固定规则找文件；换来卡片更短、没有重复路径。
- 徽标按 1.45em 估算会略宽于平台排版（中文标签多一点右侧留白），但不会再触发截断告警。
- `单独测试此节点` 只在多选菜单出现：单选时 `立即测试此节点` 已经是同一语义，重复列两项只会增加噪音。
- 详情面板保持固定 148px，列表缩短但不重新计算内容位置；打开详情时行会自然上移，不额外滚动。

## 影响

- `internal/gui/view_speedtest.go`（徽标、列表视口、详情）、`state.go`（条目字段与 `order`/视口）、`format.go`（`pathFormBadge`）、`contextmenu.go` + `ids.go`（菜单项）、`actions.go`（去掉订阅缓存路径赋值）。
- Driver 测试 41 → 43：新增「路径只显示一条 + 徽标」「详情打开后视口行不缺失」；多选菜单用例补「单独测试此节点只测指向节点」。
- headless 走查增加 `软路径` 与 `单独测试此节点` 断言；`layout` 仍 0 problems。
- 绘制仍 0 allocs/op；每行多画一个协议徽标，300 节点基准从约 66µs 升到约 95µs（只画可见行），空闲不绘制。
