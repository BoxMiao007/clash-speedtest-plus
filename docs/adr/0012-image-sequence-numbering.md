# 产物序号：跨运行延续的目录计数，不从 1 重计

批量测试（多轮测速）的结果图会积累在程序目录里，全靠时间戳分不清先后。给产物文件名加 `N.` 序号，语义是「这是第 N 次测试的结果」，而不是「本次运行里的第 N 轮」：

- **跨运行延续**：启动时扫描图目录里已有的带号图（文件名以 `数字.` 开头的 png），从最大号 + 1 接着编。上次测到 `2.`，这次就从 `3.` 起；单轮也编（每次测试都是目录序列的一环）。
- **本次运行内按队列位置递增**：起始号 + 轮在队列里的位置。跳过的轮（0 节点）也占号，图上的号和测速界面显示的「第 X/N 轮」对得齐；按出图张数重排会错位。
- **同轮同号**：输出配置与结果图共用轮次号，起始号只扫图目录（图固定写在程序目录，输出配置可能在 `-o` 指定的另一个目录，两处历史不同步，各自扫会错号）。
- **独立于「产物跟随文件名」开关**：开关只管基名跟随；序号是排序维度，关着也加（`3.clash-speedtest-plus-时间戳.png`）。
- **旧版无号图不计数**：换版前目录里的 `clash-speedtest-plus-时间戳.png` 没有 `N.` 前缀，不算进历史，新图从 1 起。

替代方案是从 1 重计（每次运行自成一列）被否：目录里的图会互相撞号、靠时间戳才能分辨，序号失去意义。Esc 中断的轮没写盘、自然不占号；回选源重排后再回车会重新扫描目录接着编。
