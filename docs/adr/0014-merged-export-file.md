# 合并导出：每轮独立产物之外，多轮队列额外写一份合并文件

上游 faceair/clash-speedtest 把多个来源合并成一批一起测，输出天然只有一份文件；本仓库从 ADR-0010 起改为多源各自一轮、不混测，产物随之变成每轮各一份。但用户仍然需要上游那种「一份文件直接可用」的产物形态（粘贴进 Clash/Mihomo、托管成订阅源），逐轮文件要手工拼接才能得到。

决定：每轮独立产物完全照旧；≥2 轮的队列全部正常测完后，额外写一份「导出-合并-时间戳.yaml」——全部轮的过筛节点（与各轮写盘同一过滤口径）并集，重名节点跳过、保留先完成轮的，重命名规则同样生效。合并文件不带产物序号（不属于任何轮，时间戳已唯一），不参与 Gist/仓库上传（上传仍绑每轮各自产物）；Esc 中断（队列未正常结束）不写；单轮队列不写（与该轮产物重复）。「≥2 轮」按实际测完的轮计：解析出 0 个节点被跳过的源不计，避免与「单轮不写」矛盾。q/Ctrl+C 只是离开方式，不否决写入——全部轮测完后的 q/Ctrl+C 照写，中途退出留下没测完的轮，自然不写。合并文件写失败只在 stderr 提示、退出码不受影响：它是测速之外的额外产物，不拖垮已成功的测速。

备选：不合并（逐轮文件已可用，代价是多轮用户手工拼接）；恢复上游单批单文件（推翻 ADR-0010 的来源隔离，弃）。合并只发生在导出层，测试层永远按轮隔离——这是本决定与上游的本质区别，也是「多轮测速」词条不受影响的原因。
