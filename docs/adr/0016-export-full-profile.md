# 导出文件：完整可用 profile，而非纯节点清单

输出配置（各轮导出、合并导出、命令行 `-o` 共用同一条写盘路径）此前只含 `proxies` 一个字段，外加一行序列化噪音 `proxy-providers: {}`（结构体字段无 omitempty，nil map 被 yaml 库渲染成空 map）。文件能通过内核 `-t` 校验，但导入 Clash 客户端后没有可切的分组、规则模式下流量无处安放，要手工补配置才能用；实际使用中被用户直接判「格式错误」拒收（v2.4.x 反馈）。

决定：导出写完整可用 profile——`mixed-port: 7890`；「节点选择」select 组（成员「自动选择」+ 全部过筛节点）；「自动选择」url-test 组（全部节点、`http://www.gstatic.com/generate_204`、间隔 300s）；rules：回环与私网直连、`GEOIP,CN,DIRECT`、`MATCH,节点选择`。IP 直连规则均带 `no-resolve`：避免内核匹配 IP 规则时对域名做 DNS 解析。除骨架外不加任何字段（不带 mode/log-level/dns 等，客户端自己管这些）。过筛后没有节点时退回纯节点清单照写（`proxies: []`、无组无规则）：空组引用是无效配置，而「输出开着必写文件」是既有预期。节点名与组名撞名时组名追加 `-1` 避让（多组同时撞则逐个避让），rules 引用最终落定的组名，不改用户节点名。序列化层补 omitempty，空 `proxy-providers` 行随之消失。

备选：维持纯节点清单（最小改动，但客户端里仍不可直接用，问题原样存在）；只给合并导出加骨架（两套形态口径，心智负担与测试面翻倍）；骨架规则做成可配置（YAGNI，先定一个能用的默认，有真实需求再议）。导出形态属用户可见功能变化，版本号走次位：v2.5.0（ADR-0009）。
