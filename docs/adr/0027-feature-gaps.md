# ADR-0027：功能缺失补齐（快速模式判定、导出重试、语法提示等）

- 状态：已接受
- 日期：2026-10-30
- 关联：[ADR-0024](0024-audit-fixes.md)、[ADR-0025](0025-followup-fixes.md)、[规格 0001](../specs/0001-viva-gui.md)

## 背景

按规格做了一轮功能缺失核对，确认以下问题不是风格问题而是「规格要求、实现没做到或只做一半」：

1. 快速模式只测延迟，`download_speed` 为 0，但 `resultOK` 无条件要求下载速度 > 0 → 所有快速模式结果被判失败，「排除上次失败」会把整批刚测的节点取消勾选。
2. 手动「导出配置」的序号来自只扫 PNG 的 `NextImageSequence`；结果图关闭或自定义目录时序号恒为 1，重复导出会静默覆盖同名 yaml。
3. 自动导出失败后没有重试入口：错误只写进 `round.err` 和页脚，结果条仍显示「本轮完成」，队列永久停住，用户只能重测。
4. 简化过滤的语法提示只在输入框占位符里，输入后消失，与「界面内显示语法提示」不符。
5. 条目读取失败时只在左侧卡片和页脚有提示，节点组标题没有错误态；面板折叠后完全看不到。
6. 设置页不校验测速服务器 URL 与重命名模板，非法值延迟到开测/导出才暴露，模板错误还是静默回退。
7. 「排除上次失败」只处理已勾选条目，与「所有」的字面语义不符。
8. 订阅轮在自定义输出模式下只靠序号防覆盖，跨运行仍会撞名；规格明确要求时间戳。
9. 只读数据目录下 mihomo 内核 home 未重定向，可能写到用户主目录。
10. 手动导出失败也会触发挂起轮的补写（上一轮引入的条件漏了 `event.err == nil`）。

## 决策

1. **失败判定按模式**：`resultOK(result, mode)`；快速模式只要求延迟 > 0 且无 `download_error`，不按下载速度判；下载/完整模式保持「下载速度 > 0」。持久化的 `ok` 用当次测速模式计算。
2. **手动导出路径唯一**：`freeManualExportPath` 从序号起按文件是否存在递增，配置 yaml 不再覆盖同名旧产物。
3. **导出失败可重试**：结果条显示当前轮「导出失败：…」，并出现「重试导出」按钮；重试清掉 `round.err` 后重新写该轮，成功后走正常自动推进。手动导出失败不再补写挂起轮。
4. **语法提示常驻**：简化模式在过滤条第二行固定显示「空格分隔；! 排除；* 任意长度；? 一个字符；例：香港 *IPLC !试用」；错误信息占用同一行。
5. **组标题错误态**：`entry.loadErr != ""` 时组标题追加红色「读取失败」。
6. **设置保存时校验**：测速服务器必须是 http(s) URL；重命名模板用 `text/template` 预解析，失败不保存并就地报错。
7. **排除上次失败遍历所有条目**（含未勾选），再次勾选时不会留下漏网失败节点。
8. **订阅无基名始终加时间戳**：自定义输出下 `序号.导出-时间戳.yaml`，跨运行不覆盖。
9. **只读也固定内核 home**：`constant.SetHomeDir(<程序目录>/data/mihomo)` 无条件执行，创建失败只记日志，宁可写失败也不漂移到主目录。
10. 手动导出事件补写条件加 `event.err == nil`。

## 取舍

- 快速模式的历史 `ok=false` 不会被自动改写（旧结果按当时判定保留），重新测一次即修正。
- 组标题只显示「读取失败」，详细原因仍在卡片与状态栏；无节点的错误条目仍不会单独成组。
- 「重试导出」只在当前轮有 `err` 时出现，不提供「全部重试」；重试成功后按正常队列继续。
- 语法提示行固定占 20px，表格整体下移；窄窗口仍可折叠/滚动。
- 服务器 URL 校验只接受 http(s)，与本项目订阅地址的约束一致。
