# 产物跟随文件名：结果图与输出配置带上所测配置的基名

> 已被 ADR-0013 取代：开关与 `-name-from-config` flag 已删除，行为恒定开启。

多轮测速后产物多了，全叫 `clash-speedtest-plus-时间戳` 分不清哪个机场。「产物跟随文件名」（界面默认开、命令行 `-name-from-config` 默认关，照「结果图只留有速度」的先例）让产物名带上所测配置文件的基名：

- 结果图：基名替换 `clash-speedtest-plus` 前缀（`机场A-20260927-153000.png`）。
- 输出配置（用户填了 `-o` / 输出路径时）：基名插在用户指定文件名前（`机场A-result.yaml`），用户点名的文件名仍然是主干。

订阅源轮没有可跟的文件名：结果图保持默认名；输出配置加时间戳（`result-20260927-153001.yaml`），防多个链接轮写同一个用户路径互相覆盖。开关关着时完全不动用户指定路径，沿用原覆盖语义。

基名经过清洗：取基名、剥 yaml 扩展、剔除文件系统非法字符与控制字符、超长截断到 40；清洗收不出有效字符时退回默认命名。拉取写出的临时文件名（`clash-speedtest-plus-sub-*`）绝不进产物名。输出路径只在队列开始锚定一次，每轮从原始路径算各自的最终名，基名不会层层叠加；保存与上传读同一个最终路径。
