# ADR-0020：合并「节点选择」与「测速结果」为单一「测速」视图

- 状态：已接受
- 日期：2026-10-30
- 关联：[ADR-0017](0017-viva-gui.md)（GUI 架构）、[ADR-0018](0018-tui-parity.md)（功能补齐）、[ADR-0019](0019-interaction-polish.md)（交互补全）、[规格 0001](../specs/0001-viva-gui.md)

## 背景

ADR-0018 把 GUI 扩成 `节点选择` / `测速结果` / `设置` 三视图：左边选节点，点「下载速度」后自动跳到结果视图。实际使用时两个视图展示的是同一批节点，切换后条目面板、勾选上下文和刚看的位置都消失；用户明确提出「节点选择 和 测速结果 功能合并在一起不单独区分」。

旧 TUI 本身就是一张表：勾选、测速、看速度、排序都在同一处。合并回一张表也更接近用户已有的操作习惯。

## 决策

1. **两个视图**：`测速` | `设置`。`测速` 左侧仍是「节点来源」面板，右侧是一张按条目分组的节点表；每行 = 复选框 + 节点名（副标题 `server:port · 类型`）+ 状态、延迟、抖动、丢包、下载速度、上传速度（完整模式）、上次测速。
2. **行交互二选一**：复选框负责勾选，点行打开/收起详情。合并前两个视图分别用「点行勾选」和「点行详情」，合并后必须选一个；详情是低频但需要精确入口的操作，勾选还有组内 `全选/全不选`、右键菜单和复选框，因此把行点击留给详情，符合表格习惯。
3. **排序在分组内进行**。分组必须保留：它承载按条目分轮的上下文与组内全选。跨组全局排序会打乱分组，因此表头排序对每个条目分组分别应用，组顺序仍是条目顺序。`nodeState.order` 记录节点在文件里的原始序号，排序主键相同时用它兜底：未测速时列表保持读取顺序，不会因为身份哈希变成随机顺序。
4. **工具条拆成两行**：第一行是 `已选 N / 共 M 个节点`、`排除上次失败`、`读取节点` 与 `下载速度`（运行中换成 `暂停`/`继续`、`停止测速`）；第二行是结果条，放进度文案、`上一轮`/`下一轮`、导出按钮。结果条只在跑过测速、有结果或正在导出时出现，第一次打开把纵向空间留给列表。
5. **轮次切换改为滚动定位**。列表始终显示全部条目分组的全部节点，不因换轮隐藏；`上一轮`/`下一轮` 把该轮条目所在分组滚到视口顶部，进度文案与手动导出跟随该轮；自动推进同样滚动。这样多轮时既能看见所有结果，也保留「查看某一轮」的能力。
6. **删掉独立结果视图的残留**：`返回选择` 按钮、结果列表与其滚动条、`view_results.go` 移除；手动导出入口挪到结果条；`view_nodes.go` 与结果表合并为 `view_speedtest.go`。
7. **绘制仍 0 allocs/op**。合并后表头每帧都在绘制路径里，原先 `"按"+label+"排序"` 的无障碍文案改为在状态变化时预计算（`sortHit*` 字段），否则每个表头每帧分配一次字符串。

## 取舍

- 点行不再切换勾选。单独勾选一个节点需要点复选框、用组按钮或右键菜单；换来稳定的详情入口。
- 列表不再按轮过滤。多轮时同屏显示所有节点，轮次通过滚动定位与进度文案区分；结果条上的导出只针对当前轮（沿用原语义）。
- 排序只在组内。想跨条目比较只能看合并导出或手动导出，界面不提供全局排序。
- 每行 7–8 列在 1180 宽下节点名约 210px，窗口更窄时节点名会省略；这是把选择与结果放进一张表的直接代价。
- 每次重绘比合并前贵：1180×800、300 节点（只画可见行）从约 48µs 升到约 66µs，因为每行多画四到五列结果。应用空闲不重绘，只有交互/测速事件时重绘，可接受。

## 影响

- 新增 `internal/gui/view_speedtest.go`；删除 `view_nodes.go`、`view_results.go`；`app.go`、`state.go`、`ids.go`、`scrollbar.go`、`actions.go` 有对应调整。
- `viewKind` 收敛为 `viewTest` / `viewSettings`；`s.results` 仍作为「当前轮已测结果」的扁平集合供进度文案、手动导出与测试使用，但不再驱动独立列表。
- Driver 测试从 40 增至 41：新增多轮滚动定位用例，详情用例补「点行不改勾选 / 点复选框不打开详情」契约。
- 规格、GLOSSARY、README、AGENTS 与验证记录同步；headless 走查改用 `测速` 标签并去掉 `返回选择`。
