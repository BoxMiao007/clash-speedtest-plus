## 3. headless 线协议走查

脚本：`scripts/headless-walkthrough.sh`（构建 `-tags vivahead`，`VIVA_HEADLESS=1`，不打开窗口；非截图命令不创建 D3D 渲染器，不依赖 GPU）。完整输出：`docs/validation/headless-walkthrough.log`。

走查命令（真实二进制）：

```
size / texts / hits
click "选择节点 机场 A / HK-02"、click "选择节点 机场 A / JP-01"
rightclick "节点 机场 A / HK-01"、texts、click "复制此节点信息"、clip
click "下载速度"、waitfor "已完成 1/1" 30000、texts
click "返回选择"
click "过滤表达式"、type HK !02、key enter、texts
find "节点 机场 A / HK-01"、find "节点 机场 A / JP-01"
click "保存预设"、click "预设名称"、type 只看HK、click "保存"
click "新建条目"、click "名称"、type 机场 B、openfiles <临时目录>\b.yaml、click "选择文件…"、click "保存"
texts、layout、quit
```

断言结果：

- 启动 `ok ready 1180x800 scale=2`；条目、分组、节点、「未测试」文案出现。
- 右键出现「复制此节点信息」，复制后 `clip` 含节点名。
- 真实引擎对 `127.0.0.1:1` 节点快速失败；结果视图出现「已完成 1/1」与「失败」。
- 过滤后 `find` 能找到 HK-01、找不到 JP-01。
- 预设 `只看HK` 写入 `data/presets.json`。
- 新建条目 `机场 B` 写入 `data/entries.json`，路径落为软路径 `b.yaml`。
- `data/results.json` 含 `"ok": false` 的失败结果。
- `layout` 返回 `ok 0 problems`。
- 脚本退出码 0，打印 `PASS：headless 走查通过`。

## 4. 绘制分配与耗时

```
$ go test ./internal/gui -run '^$' -bench 'BenchmarkPaint' -benchmem -count=1 -benchtime=2000x
BenchmarkPaintNodeList-16    2000   47481 ns/op   275 B/op   0 allocs/op   # 300 节点
BenchmarkPaintSmallList-16   2000   43741 ns/op   270 B/op   0 allocs/op   # 20 节点
BenchmarkPaintEmpty-16       2000   12727 ns/op    62 B/op   0 allocs/op
```

口径：直接调用应用 `Paint`（含 flex 布局、Viva Windows 文本引擎塑字、命中/场景声明），不含 GPU 上传与呈现；`-benchtime=2000x` 取稳定态（单帧暖机阶段会多 1–4 次框架内部分配）。节点列表只绘制视口内行，300 节点与 20 节点的每帧分配都实测为 0，耗时同量级（约 47 µs vs 44 µs）。

## 6. 未用真实窗口验证的项目

按规格 10.4，以下未验证，交付时不声称已覆盖：

- IME 组合输入、候选窗定位；
- 真实键盘布局与输入法下 Enter/Esc/Tab 行为；
- 焦点丢失/恢复（Alt+Tab、点击其它窗口）；
- 高 DPI 缩放与多显示器；
- 窗口管理器关闭、最大化/还原、标题栏行为；
- 真实 GPU 渲染外观（颜色/抗锯齿/字体回退）与稳定帧率；
- 系统文件对话框的真实交互（Driver 用 `QueueOpenFiles` 拦截）；
- macOS / Linux 实机（本机仅 Windows）。

补充：本次验证没有主动打开真实窗口。评审过程中一名协作者误运行过一次构建产物、短暂开窗后立即 taskkill；该次运行未用于任何结论，也未改动仓库。除这次误启动外，窗口相关行为均未验证。

## 7. 已知限制

- 条目只读本地文件；不支持远程订阅 URL（旧 CLI 的订阅地址、Gist/仓库上传、结果图/TSV、导出配置、IP 改名、阈值过滤、提前停止、多轮队列已随 TUI/CLI 移除）。
- 文件里的 `proxy-providers` 只支持 `type: http`；`file`/`inline` provider 会跳过并写日志。provider 缓存通过 `constant.SetHomeDir` 落在 `<程序目录>/data/mihomo/`。
- 发布矩阵只含 Windows/Linux（amd64、arm64）：Viva 的 macOS 后端依赖 cgo，需在 Mac 上 `CGO_ENABLED=1` 从源码构建；旧的 386/arm32 目标不再发布。
- 结果写入 `results.json` 是整文件重写；每个结果写一次，未做批量/异步落盘。
- 启动时同步读取全部条目节点（含 `proxy-providers` 网络拉取）；文件或网络很慢时首帧会等待，当前没有进度提示。
- 明示一个取舍：过滤只影响列表显示，不改变节点的勾选；开始测速仍会测所有勾选节点（包括被过滤隐藏的）。这与「过滤是列表视图工具」一致，避免隐藏节点被静默排除。
