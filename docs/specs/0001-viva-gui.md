# 订阅测速工具 Viva GUI 规格

> 状态：已实现。第一版 GUI 于 2026-10-29 合入 `main`；2026-10-30 按「与旧 TUI 功能等价」补齐订阅、参数、导出、上传、重命名、多轮与暂停（[ADR-0018](../adr/0018-tui-parity.md)）。
> 验收记录：[2026-10-29-viva-gui.md](../validation/2026-10-29-viva-gui.md)、[2026-10-30-tui-parity.md](../validation/2026-10-30-tui-parity.md)。
> 关联：GitHub Issue #26。
> 本文是该功能的**唯一需求基线**。上下文被压缩后，先读本文件再动代码。

## 1. Problem Statement

旧版 clash-speedtest-plus 同时维护 TUI（`picker/`、`tui/`）和 CLI（根目录 `main.go` 的 flag 逻辑）。用 Viva 重写为单一 GUI 后，第一版只覆盖了「本地文件条目 + 勾选节点 + 测下载速度」，把订阅地址、测速参数、阈值过滤、导出配置、结果图、TSV、Gist/仓库上传、IP 归属地重命名、多轮队列、暂停/继续全部砍掉，导致测完的节点没有可用产物，实际无法替代 TUI。

本次补齐目标：在不改回 TUI/CLI 的前提下，把上述能力做进 Viva GUI，行为口径与旧 TUI 一致。

## 2. Solution

单窗口 Viva 应用，三个视图（`节点选择` / `测速结果` / `设置`）：

- 左侧「节点来源」面板管理条目：本地配置文件或 http(s) 订阅地址；新建 / 重命名 / 修改 / 删除 / 读取 / 重新获取。
- 右侧「节点选择」按条目分组展示节点，复选框选择，组内全选/全不选，一键「排除上次失败」。
- 顶部过滤条：简化关键词模式（默认）与完整正则模式随时切换；预设可命名保存、应用、覆盖、重命名、删除，跨条目通用。**过滤结果同时决定测哪些节点与导出哪些节点**（与旧 TUI 的 `-f` 一致）。
- 点「下载速度」按钮开始测速：每个选中条目各一轮，自动推进；结果视图实时按当前排序列重排。
- 测速中可暂停/继续、停止；可设置提前结束数量。
- 每轮完成按输出模式自动写配置 yaml（完整 profile 骨架）、结果图 PNG、并可选上传 Gist/仓库；多轮全部完成后额外写「合并导出」。
- 结果视图支持点表头排序、点行展开详情、手动导出配置/结果图/结果表。
- 设置页覆盖测速模式、下载/上传大小、超时、并发、并行、服务器、UA、提前结束、四项阈值、输出模式与路径、结果图、重命名、上传凭据。
- 所有持久化数据放在 `<程序目录>/data/`；条目路径支持软路径与硬路径。

## 3. 硬性规范（评审会拒）

1. 只用 Viva 组件与绘制模型；无 WebView / HTML / CSS / JS。
2. 空闲不绘制：应用空闲时没有常驻 goroutine / 定时器 / 轮询。测速、订阅拉取、导出与上传的 goroutine 只在任务期间存在，完成后必须退出。
3. 绘制 / 布局 / 输入 / 场景路径中无反射、无 `map[string]any`、无 per-paint 分配。**所有显示字符串在状态变化时预计算**；绘制函数只读状态、不拼接字符串。
4. 命中目标不手写编号：一律 `ui.Tree` 的 `Feature` / `ID`；节点行标识由「条目 ID + 节点稳定身份」在数据读取时注册，帧间稳定，列表实时重排不改变行 ID。
5. 点击事件在控件声明处用 `.Clicked()` / `.Picked()` / `.Submitted()` / `canvas.PointerOn` 处理。
6. 布局用 `flex`；主题只用 `ui.LightTheme()` 的官方令牌，不新造颜色体系。
7. 阻塞操作（系统文件对话框、订阅拉取、导出、上传）不得在 Paint / 布局中同步执行；网络与字体渲染放后台 goroutine，结果经 pending 队列回到窗口线程。
8. 新增依赖必须测量 stripped 二进制体积、启动时间、空闲内存，并如实报告测量方法；不做无测量依据的性能声明。
9. 用户可见文案用简体中文；标识符、协议字段保持原文。

## 4. 数据目录与路径

### 4.1 数据目录

- 程序目录 = `os.Executable()` 所在目录（解析软链接后取 `filepath.Dir`）。
- 数据目录 = `<程序目录>/data/`。**不写**用户主目录、AppData、注册表等。
- 测试可注入 `Options.DataDir`；生产代码不得有其它覆盖入口。
- 启动时创建数据目录并做可写探针。不可写 / JSON 损坏时：应用照常打开，但显示明确错误对话框，**禁用持久化**，不静默改存其它位置。所有后续写入尝试在状态栏报错。

数据目录布局：

```
<程序目录>/data/
  settings.json        # 过滤、测速参数、阈值、输出、重命名、上传
  entries.json         # 节点来源条目（本地文件 / 订阅地址）
  presets.json         # 过滤预设
  results.json         # 按条目 ID + 节点身份保存的测速结果
  subscriptions/       # 订阅正文缓存（<条目 ID>.yaml），重新获取时整文件替换
  mihomo/              # proxy-providers 的内核缓存（使用 provider 时产生）
```

数据文件版本为 `"version": 2`（第一版为 1）。加载时版本大于 2 视为错误（禁用持久化）。版本 1 的设置/条目按字段缺失读取，缺失字段由默认值补齐。写入用「同目录临时文件 + rename」原子替换。

### 4.2 软 / 硬路径

- 条目存储值二选一：
  - 软路径：相对程序目录、以 `/` 分隔（跨平台可读），例如 `test/a.yaml`；
  - 硬路径：各系统原生绝对路径，例如 `D:\订阅\a.yaml`、`/home/u/a.yaml`。
- 保存时：绝对路径落在程序目录内 → 自动转软路径；否则存清理后的绝对路径。
- 解析时：软路径 `filepath.FromSlash` 后相对程序目录拼接；绝对路径原样。
- 界面上每个条目显示当前形态：`软路径 · test/a.yaml` 或 `硬路径 · D:\订阅\a.yaml`，并显示解析后的绝对路径（省略号截断）。
- Windows 下程序目录包含判断大小写不敏感；Unix 大小写敏感。
- 文件不存在 / 解析失败：条目卡片与节点组显示明确错误，不静默失败；保留旧节点列表（如已有），不覆盖成空。

## 5. 条目模型

```go
type Entry struct {
    ID   string `json:"id"`             // crypto/rand 16 字节 hex，创建时生成
    Name string `json:"name"`           // 非空、唯一
    Kind string `json:"kind,omitempty"` // "local"（空值同义）或 "subscription"
    Path string `json:"path,omitempty"` // 本地：软路径（/ 分隔）或硬路径（绝对）
    URL  string `json:"url,omitempty"`  // 订阅：http(s) 地址
}
```

操作：新建（名称 + 类型 + 路径对话框或订阅地址）/ 重命名 / 修改 / 删除（二次确认）。条目数据持久化于 `entries.json`。

### 5.1 本地文件条目

- `读取` 直接解析文件；`重新获取` 重新解析同一文件。
- 节点身份 = `sha256(协议 + 0 + 名称 + 0 + server + 0 + port + 0 + 规范化参数序列化)` 前 16 位 hex；参数用 `yaml.v2` 序列化（排序键，且能处理 `map[interface{}]interface{}` 嵌套参数）。同一文件内身份完全相同的节点按出现顺序追加 `#2`、`#3`。
- 与新列表身份匹配的已测节点：保留原测试结果与上次测速时间；新节点为「未测试」；消失的节点从列表移除；已持久化结果不删除。
- 已有节点保留上次的勾选状态；新节点默认选中。

### 5.2 订阅条目

- 地址只接受 `http://` / `https://` 开头；保存前校验。
- 拉取使用 `internal/speedtester.FetchSubscriptionBody`：先按原样 Clash/Mihomo yaml 接受，再试整段 base64，最后在没有 `flag` 参数时补 `flag=meta` 重试；全部失败报「订阅内容不是 Clash/Mihomo 配置」。
- 拉取请求带「拉取 UA」设置；为空时用内核默认 UA。
- 拉取成功后正文写入 `data/subscriptions/<条目 ID>.yaml`，再从正文解析节点（proxy-providers 的远程节点也按同一 UA 拉取）。
- 读取规则：
  - 启动时只用缓存，不联网；缓存缺失显示「尚未拉取订阅」。
  - 点 `读取缓存`：有缓存读缓存，没有缓存才异步拉取。
  - 点 `重新获取`：始终重新拉取并覆盖缓存。
  - 新建条目 / 修改地址后立即异步拉取。
- 拉取失败保留旧节点列表并在条目卡片与状态栏显示错误。
- 订阅条目没有可跟随的本地文件名，产物命名用时间戳兜底（见 8.7）。

## 6. 节点读取与选择

- 两种读取并存：
  - 自动读取：勾选条目（选中）后自动读取该条目节点；
  - 手动读取：工具栏「读取节点」按钮，读取全部选中条目的节点。
- 节点列表**按条目分组**，组标题 = 条目名。不同条目的节点不合并；跨条目同名节点各自独立成行。
- 新读取节点默认全选；可单个/多个取消勾选；每组有 `全选` / `全不选`（作用于该组当前可见节点）。
- 「排除上次失败」按钮：取消所有「上次结果失败」节点的勾选。失败定义（结果写入时计算并持久化 `ok`）：
  - 延迟为 0（全部 ping 失败），或
  - `download_error` 非空，或
  - 下载速度 ≤ 0。
- 选中态用 `flex.Checkbox`（明确开关控件），整行点击也可切换勾选。
- 节点行信息：节点名、类型、`server:port`、上次测速时间（未测试显示「未测试」）、上次结果摘要（有则显示速度或「失败」）。

## 7. 过滤

### 7.1 简化模式（默认）

- 空格分隔多个 token；`!` 前缀为排除词；支持 `*`（任意长度）与 `?`（恰好一个字符/汉字）通配；大小写不敏感。
- 正向词之间可选「与 / 或」：与 = 全部匹配，或 = 任一匹配。排除词始终是否定条件（任何匹配即排除）。
- 空表达式匹配全部。token 只有 `!` 是非法表达式。
- 必须比手写正则易用；界面内显示语法提示。例：`香港 *IPLC !试用`。

### 7.2 高级模式

- 完整 Go 正则（RE2），区分大小写，空表达式匹配全部。
- 与简化模式随时切换；非法正则行内报错「正则表达式无效：…」，保留上一个有效过滤器继续显示，不崩溃、不清空。
- 过滤只匹配节点名（界面注明）。

### 7.3 过滤范围

- 过滤结果同时用于：
  - 节点列表显示；
  - 点「下载速度」时实际测速的节点集合（选中 ∩ 过滤命中）；
  - 导出时的节点集合（先取本轮测得的结果，再叠加 8.6 的阈值过滤）。
- 这样与旧 TUI 的 `-f` / `-b` 语义一致：过滤掉的节点既不显示也不测。

### 7.4 预设

- 预设 = `{名称, 模式, 表达式, 组合方式}`，命名唯一，跨条目通用，保存于 `presets.json`。
- 操作：应用（下拉选中即生效）、保存当前为预设（同名覆盖）、重命名、删除。

## 8. 视图与交互

### 8.1 三视图

- 顶部视图切换：`节点选择` | `测速结果` | `设置`（分段控件）。默认节点选择。
- 工具栏 `下载速度` 按钮：开始测速并自动切到测速结果视图。
- 过滤条在两个视图都显示；设置视图也保留（过滤设置属于全局）。

### 8.2 节点选择视图

- 左侧条目面板：标题「节点来源」、`新建条目`；每个条目卡片：名称、路径形态 + 解析路径（订阅显示地址与缓存路径）、状态/节点数、`读取`（订阅为 `读取缓存`）`重新获取` `编辑` `删除`。
- 右侧：工具栏（`已选 N / 共 M 个节点`、`排除上次失败`、`读取节点`、`下载速度`）+ 分组节点列表（`ScrollArea`）。
- 组标题：条目名、`N 个节点 · 已选 M`、`全选` / `全不选`。
- 空态：无条目说明 + 新建提示；条目未读取显示状态；过滤无匹配提示。

### 8.3 测速结果视图

- 列：状态、节点、条目、类型、延迟、抖动、丢包、下载速度、上传速度（仅完整模式）、上次测速。
- 排序：默认 fast 模式按延迟升序、其余按下载速度降序；点表头切换排序列，再点同一列反转方向，表头显示 ▲/▼。测速中节点用瞬时速度参与排序并显示「测试中」；未测到的延迟按最差处理。
- 行命中 ID 与节点身份绑定，重排后不变。
- 工具栏：`上一轮` / `下一轮`（多轮时）、`暂停`/`继续`（运行中）、`停止测速`、`导出配置`、`结果图`、`结果表`、`返回选择`；进度与导出文案在同一行。
- 点行展开/收起详情面板：类型、服务器、条目、延迟、抖动、丢包、下载/上传速度、上次测速、错误信息。
- 空态：「还没有测速结果。回到「节点选择」，勾选节点后点「下载速度」开始。」

### 8.4 右键菜单

- 单层平铺，无子菜单；单个/多选语境文案区分（同第一版）。
- 单个节点语境：`复制此节点信息` / `立即测试此节点` / `选中此节点` / `排除此节点`。
- 多选语境：`复制所选节点信息` / `立即测试所选节点` / `取消选中所选节点` / `排除所选节点`。
- 复制文本含名称、条目、类型、服务器、上次测速、延迟、抖动、丢包、下载/上传速度与错误信息。
- 测速进行中 `立即测试…` 置灰。

### 8.5 测速编排

- 生产引擎复用 `internal/speedtester`：`New(Config)` + `SetProgressFunc` + `TestProxiesUntil(proxies, onStart, onResult)`；GUI 侧 `Runner` 接缝增加 `Configure` / `Pause` / `Resume`。
- 传给引擎的 map key 用唯一键 `<entryID>/<nodeID>`；`Result.ProxyName` 即该 key，用于回填节点。
- **多轮队列**：每个选中条目一轮，按条目顺序推进；轮内节点 = 该条目下选中且过滤命中的节点。右键「立即测试所选节点」按条目分组同样生成轮。
- 测速参数来自设置（见 8.6）；每轮开测前把参数快照交给引擎，运行中改设置只影响下一轮。
- 暂停/继续：暂停只停止派发新节点，在测节点跑完手头这一批。
- 提前结束：过筛结果数达到限额时引擎停止派发，本轮标记「提前结束」。
- 后台 goroutine 只在测速期间存在；进度回调发布到互斥保护的 pending 队列后调用 `Invalidator.Invalidate()`；`OnWake` 在窗口线程把 pending 并入模型并重排。
- 每个结果立即持久化到 `results.json`（`tested_at`、`ok` 等）。过期轮次的迟到事件按轮次号丢弃。
- 停止：取消 context 并 `Stop()`；已产出的结果保留，剩余轮次作废，不导出。
- 同一时间只允许一轮测速；运行中禁用读取/重新获取/新建/删除条目。

### 8.6 设置视图

- 顶部：`恢复默认`、`保存设置`；下方为可滚动分区表单，非法值在保存时就地报错，不写盘。
- 测速模式：`快速`（只测延迟）/ `下载`（默认）/ `完整`（额外测上传）。
- 测速参数：下载大小（MB）、上传大小（MB）、超时（毫秒）、单节点并发、节点并行、测速服务器 URL、拉取 UA、提前结束数量。
- 结果阈值（导出与提前结束共用）：最高延迟（毫秒）、最高丢包（%，-1 = 不限制）、最低下载（MB/s）、最低上传（MB/s）。
- 输出：输出模式（`关闭` / `当前目录下` / `自定义`）、输出路径（自定义词干，自动补 `.yaml`）、`导出结果图`、`结果图只保留有速度的行`、`按 IP 归属地与速度重命名`、重命名模板（Go text/template，空 = 内置格式）。
- 上传：Gist token / 地址；仓库 token / 地址 / 文件路径 / 分支。Gist 与仓库各自要求 token 与地址同时填写。
- 保存后立即写 `settings.json` 并生效（排序默认值随模式重置）。
- 说明文案明确：口令以明文保存在 `data/settings.json`，只在本机使用。

### 8.7 导出与上传

- 每轮正常结束、且需要产物时（配置/图片/上传任一开启）在后台导出，完成后推进下一轮；导出失败保留错误并停止推进，用户可修正设置后手动导出。
- 配置 yaml 形态固定（[ADR-0016](../adr/0016-export-full-profile.md)）：`mixed-port: 7890`、`节点选择`（select）与 `自动选择`（url-test）两组、国内直连规则与 `MATCH` 兜底；组名与节点名撞名时组名避让。
- 输出模式：
  - 关闭：不写配置，也不上传；
  - 当前目录下：`<程序目录>/<基名>-导出.yaml`；订阅轮无基名，用 `导出-时间戳.yaml`；
  - 自定义：按用户词干，本地轮把基名插在文件名前（`机场A-导出.yaml`），订阅轮用时间戳防覆盖。
- 产物序号：每轮开测时取程序目录里图片序号的下一个值，按「起始序号 + 轮次位置」编号，配置与结果图同轮同号（`3.机场A-导出.yaml` / `3.机场A-….png`）。
- 结果图：PNG，含来源、汇总行、产物序号；列与配色沿用旧实现；`结果图只保留有速度的行` 仅非 fast 模式生效。
- 合并导出：≥2 轮、输出非关闭、全部轮正常完成后，额外写 `<程序目录>/导出-合并-时间戳.yaml`，内容是各轮过筛节点按完成顺序求并集，重名保留先完成轮的。
- 重命名：开启时按 `ip.GetIPLocation(server)` 的归属地 + 速度/延迟套模板；查询失败保留原名。重命名只改导出文件里的节点名，不改界面显示。
- 上传：配置写完后，按设置同步到 Gist / 仓库；上传失败只作为状态栏提示，不阻塞后续轮次，也不改变失败语义。
- 手动导出（结果视图按钮）：`导出配置`、`结果图`、`结果表`。手动导出只处理当前轮（没有轮次时处理全部历史结果），同样在后台执行；结果表写 `<程序目录>/结果表-时间戳.tsv`。

## 10. Testing Decisions

测试只测外部可依赖行为，不测像素偏移与实现细节。

### 10.1 接缝（seam）

1. **GUI 应用（最高接缝）**：`gui.New(Options)` + `App.Config()` 交给 `app.Driver`；注入临时程序目录/数据目录与假引擎。覆盖条目 CRUD、订阅拉取（本地 httptest）、自动/手动读取、分组、选择、过滤、预设、视图切换、排序、详情、轮次、暂停、设置保存、导出、持久化、数据目录错误。
2. **store 包**：路径软硬转换、设置归一化、订阅缓存读写、原子写、损坏 JSON、结果保留、跨重启读取、版本 1 兼容。
3. **filter 包**：简化/高级语义、非法表达式、大小写、Unicode 通配、零分配。
4. **output / export / ip / gist 包**：结果图与路径/序号、导出骨架与阈值过滤、重命名模板、上传请求（httptest）。
5. **headless 线协议**：`-tags vivahead` 构建 + `VIVA_HEADLESS=1`，用命令走查真实二进制。
6. 引擎不重测：保留 `internal/speedtester` 原有单测，新增订阅拉取与节点解析测试。

### 10.2 Driver 测试用例（除第一版 17 个外新增 14 个）

1. 订阅条目：新建后拉取一次、写 `data/subscriptions/<id>.yaml`、节点显示；重启只读缓存不再请求。
2. 条目种类切换：本地条目改成订阅地址后保存为订阅、地址变化强制重新拉取。
3. 多条目测速：每个条目一轮、自动推进并停在最后一轮，结果文案显示轮次。
4. 设置保存：改模式/下载大小 → 写 `settings.json` → 下一轮引擎收到新参数；完整模式结果显示上传列。
5. 输出模式「当前目录下」：测完自动写 `*-导出.yaml`，内容含 `mixed-port: 7890`、两组与 `MATCH` 规则。
6. 过滤限制测速节点：表达式命中 1 个时只把 1 个节点交给引擎。
7. 暂停/继续：状态与按钮文案切换。
8. 结果行详情：点行展开、再点收起。
9. 表头排序：切换列与反转方向改变结果顺序。
10. 手动导出结果表：写 TSV，表头与节点行齐全。
11. 停止后导出回填：已停止的轮不推进剩余轮次。
12. 提前结束计数：只数过筛结果，限额 0 不停止。
13. 导出过筛：阈值挡掉慢节点、不改原配置、缺 name/server 跳过。
14. 结果图：开启时每轮结束写出非空 PNG（程序目录与工作目录不同盘也能写）。

### 10.3 headless 走查（必须执行）

- 构建 `-tags vivahead` 到临时目录，旁边放 `data/`（含预置 `settings.json`、`entries.json`）与 `a.yaml`、`b.yaml` 夹具。
- 覆盖：视图文本、右键菜单与剪贴板、设置页改下载大小并保存、过滤、预设保存、新建条目、「下载速度」测速（夹具节点指向 `127.0.0.1:1`，快速失败，不联网）、自动导出后的状态与产物内容、`layout` 无问题、`quit`。
- 断言落盘：`settings.json` 的 `output_mode` 与 `download_mb`、`entries.json`、`presets.json`、`results.json`，以及导出 yaml 的骨架字段。

### 10.4 未用真实窗口验证的项目（交付时明确列出）

IME、焦点丢失、真实键盘、高 DPI、窗口管理器关闭、真实 GPU 渲染外观、系统文件对话框真实交互、真实订阅地址与 Gist/仓库上传、IP 归属地查询（联网）、结果图在本机字体下的最终外观。

## 11. Out of Scope

- 主题切换、国际化、数据从旧 TUI/CLI 迁移（旧版没有持久化数据）、安装包与代码签名、macOS/Linux 真机验证。
- 暂停/继续只作用于节点派发，不中断在测节点的当前请求。
- 上传凭据以明文保存在 `data/settings.json`，不做系统钥匙串集成。
- 不用真实窗口验证的项目见 10.4。
