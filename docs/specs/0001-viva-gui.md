# 订阅测速工具 Viva GUI 重构规格

> 状态：已实现并合入 `main`（2026-10-29）。验收记录见 [docs/validation/2026-10-29-viva-gui.md](../validation/2026-10-29-viva-gui.md)。
> 分支：`feat/viva-speedtest-gui`（已合回 main）。
> 关联：本文件同时发布到 GitHub Issues #26（标签 `ready-for-agent`）。
> 本文是该分支的**唯一需求基线**。上下文被压缩后，先读本文件再动代码。

## 1. Problem Statement

现在的 clash-speedtest-plus 同时维护 TUI（`picker/`、`tui/`）和 CLI（根目录 `main.go` 的 flag 逻辑），只能在终端里用。桌面用户需要：文件条目管理、按条目分组的节点列表、勾选后一键测下载速度、结果实时按速度重排；还要把条目、过滤预设、节点测试结果保存在程序目录内，拷贝整个程序目录即可迁移。

同时仓库里没有 Viva GUI 代码。本任务用 Viva（Go、GPU 原生、无 WebView/HTML/CSS/JS）重写界面，并**删除 TUI 与 CLI**，只交付 GUI。

## 2. Solution

单窗口 Viva 应用：

- 左侧「测试文件」面板管理条目（新建 / 重命名 / 修改路径 / 删除 / 读取 / 重新获取）。
- 右侧「节点选择」视图按条目分组展示节点，复选框选择，组内全选/全不选，一键「排除上次失败」。
- 顶部过滤条：简化关键词模式（默认）与完整正则模式随时切换；过滤预设可命名保存、应用、覆盖、重命名、删除，跨条目通用。
- 点「下载速度」按钮即开始测速并自动切到「下载速度」视图；结果按下载速度实时重排，行标识用节点稳定身份，重排不换 ID。
- 节点行右键菜单区分单个/多选语境，单层平铺。
- 所有持久化数据放在 `<程序目录>/data/`；条目路径支持软路径（相对程序目录）与硬路径（绝对路径），程序目录内的绝对路径保存时自动转软路径。
- 核心测速引擎与配置解析原样复用为内部包，不重写。

## 3. 硬性规范（评审会拒）

1. 只用 Viva 组件与绘制模型；无 WebView / HTML / CSS / JS。
2. 空闲不绘制：应用空闲时没有常驻 goroutine / 定时器 / 轮询。测速进行中的实时刷新属于活跃阶段，测速结束后所有后台 goroutine 与 ticker 必须停止。
3. 绘制 / 布局 / 输入 / 场景路径中无反射、无 `map[string]any`、无 per-paint 分配。**所有显示字符串在状态变化时预计算**；绘制函数只读状态、不拼接字符串。
4. 命中目标不手写编号：一律 `ui.Tree` 的 `Feature` / `ID`；节点行标识由「条目 ID + 节点稳定身份」在**数据读取时**注册（`tree.Name` / `tree.Sub` / `tree.ID` 只在加载或状态变化时调用），帧间稳定，列表实时重排不改变行 ID。
5. 点击事件在控件声明处用 `.Clicked()` / `.Picked()` / `.Submitted()` / `canvas.PointerOn` 处理。
6. 布局用 `flex`；主题只用 `ui.LightTheme()` 的官方令牌，不新造颜色体系。
7. 新增依赖（Viva）必须测量 stripped 二进制体积、启动时间、空闲内存，并如实报告测量方法。
8. 不做无测量依据的性能声明。
9. 用户可见文案用简体中文；标识符、协议字段保持原文。

## 4. 数据目录与路径

### 4.1 数据目录

- 程序目录 = `os.Executable()` 所在目录（解析软链接后取 `filepath.Dir`）。
- 数据目录 = `<程序目录>/data/`。**不写**用户主目录、AppData、注册表等。
- 测试可注入 `Options.DataDir`；生产代码不得有其它覆盖入口。
- 启动时创建数据目录并做可写探针（创建临时文件再删除）。不可写 / JSON 损坏时：应用照常打开，但显示明确错误对话框，**禁用持久化**，不静默改存其它位置、不散落数据。所有后续写入尝试在状态栏报错。

数据目录布局：

```
<程序目录>/data/
  settings.json   # 过滤模式/表达式/组合方式
  entries.json    # 测试文件条目
  presets.json    # 过滤预设
  results.json    # 按条目 ID + 节点身份保存的测速结果
  mihomo/         # proxy-providers 的内核缓存（使用 provider 时产生）
```

每个 JSON 带 `"version": 1`；加载时版本大于 1 视为错误（禁用持久化）。写入用「同目录临时文件 + rename」原子替换。

### 4.2 软 / 硬路径

- 条目存储值二选一：
  - 软路径：相对程序目录、以 `/` 分隔（跨平台可读），例如 `test/a.yaml`；
  - 硬路径：各系统原生绝对路径，例如 `D:\订阅\a.yaml`、`/home/u/a.yaml`。
- 保存时：绝对路径落在程序目录内 → 自动转软路径；否则存清理后的绝对路径。
- 解析时：软路径 `filepath.FromSlash` 后相对程序目录拼接；绝对路径原样。
- 界面上每个条目显示当前形态：`软路径 · test/a.yaml` 或 `硬路径 · D:\订阅\a.yaml`，并显示解析后的绝对路径（省略号截断）。
- Windows 下程序目录包含判断大小写不敏感；Unix 大小写敏感。
- 文件不存在 / 解析失败：条目卡片与节点组显示明确错误，不静默失败；保留旧节点列表（如已有），不覆盖成空。

## 5. 条目模型

```go
type Entry struct {
    ID   string `json:"id"`   // crypto/rand 16 字节 hex，创建时生成
    Name string `json:"name"` // 非空、唯一
    Path string `json:"path"` // 软路径（/ 分隔）或硬路径（绝对）
}
```

操作：新建（名称 + 系统文件对话框选路径）/ 重命名 / 修改路径（系统文件对话框）/ 删除（二次确认）。条目数据持久化于 `entries.json`。

「重新获取节点」：

- 每个条目卡片有 `重新获取` 按钮，重新读取该文件。
- 节点身份 = `sha256(协议 + 0 + 名称 + 0 + server + 0 + port + 0 + 规范化参数序列化)` 前 16 位 hex；参数用 `yaml.v2` 序列化（排序键，且能处理 `map[interface{}]interface{}` 嵌套参数）。同一文件内身份完全相同的节点按出现顺序追加 `#2`、`#3`。
- 身份不依赖列表顺序、不依赖临时 ID。
- 与新列表身份匹配的已测节点：保留原测试结果与上次测速时间；新节点为「未测试」；消失的节点从列表移除。持久化结果不删除（节点以后重新出现仍可恢复）。
- 已有节点保留上次的勾选状态；新节点默认选中。

## 6. 节点读取与选择

- 两种读取并存：
  - 自动读取：勾选条目（选中）后自动读取该条目节点；
  - 手动读取：工具栏「读取节点」按钮，读取全部选中条目的节点。
- 节点列表**按条目分组**，组标题 = 条目名。不同条目的节点不合并；跨条目同名节点各自独立成行。
- 新读取节点默认全选；可单个/多个取消勾选；每组有 `全选` / `全不选`（作用于该组当前可见节点）。
- 「排除上次失败」按钮：取消所有「上次结果失败」节点的勾选。失败定义（结果写入时计算并持久化 `ok`）：
  - 延迟为 0（全部 ping 失败），或
  - `download_error` 非空，或
  - 下载速度 ≤ 0。
- 选中态用 `flex.Checkbox`（明确开关控件，视觉差异显著），整行点击也可切换勾选。
- 节点行信息：节点名、类型、`server:port`、上次测速时间（未测试显示「未测试」）、上次结果摘要（有则显示速度或「失败」）。

## 7. 过滤

### 7.1 简化模式（默认）

- 空格分隔多个 token；`!` 前缀为排除词；支持 `*`（任意长度）与 `?`（恰好一个字符/汉字）通配；大小写不敏感。
- 正向词之间可选「与 / 或」：与 = 全部匹配，或 = 任一匹配。排除词始终是否定条件（任何匹配即排除）。
- 空表达式匹配全部。token 只有 `!` 是非法表达式。
- 必须比手写正则易用；界面内显示语法提示。例：`香港 *IPLC !试用`。

### 7.2 高级模式

- 完整 Go 正则（RE2），区分大小写，空表达式匹配全部。
- 与简化模式随时切换；非法正则行内报错「正则表达式无效：…」，保留上一个有效过滤器继续显示，不崩溃、不清空。
- 过滤只匹配节点名（界面注明）。

### 7.3 预设

- 预设 = `{名称, 模式, 表达式, 组合方式}`，命名唯一，跨条目通用，保存于 `presets.json`。
- 操作：应用（下拉选中即生效）、保存当前为预设（同名覆盖）、重命名、删除。
- 过滤条显示：模式分段控件「简化 / 正则」、表达式输入框、「与 / 或」分段（仅简化模式）、预设下拉、`保存预设` / `重命名预设` / `删除预设`（后两个仅选中预设时出现）。

## 8. 视图与测速交互

### 8.1 双视图

- 顶部视图切换：`节点选择` | `下载速度`（分段控件）。默认节点选择。
- 工具栏 `下载速度` 按钮：开始测速并自动切到下载速度视图。

### 8.2 节点选择视图

- 左侧条目面板：标题「测试文件」、`新建条目`；每个条目卡片：名称、路径形态 + 解析路径、状态/节点数、`读取` `重新获取` `编辑` `删除`。
- 右侧：工具栏（`已选 N / 共 M 个节点`、`排除上次失败`、`读取节点`、`下载速度`）+ 分组节点列表（`ScrollArea`）。
- 组标题：条目名、`N 个节点 · 已选 M`、`全选` / `全不选`。
- 空态：
  - 无条目：说明文字 + `新建条目` 按钮；
  - 条目未读取：组内「未读取」行；
  - 过滤无匹配：「没有节点匹配当前过滤条件。」

### 8.3 下载速度视图

- 列：状态、节点、条目、类型、延迟、丢包、下载速度、上次测速。
- 排序：按「有效下载速度」降序；测速中节点用瞬时速度参与排序并显示「测试中」；无速度的依次为失败、等待中，排在后面；同速按节点身份稳定排序。
- 每次有结果/瞬时速度变化时在状态变化路径重排一次（不是每帧）。
- 行命中 ID 与节点身份绑定，重排后不变。
- 工具栏：`返回选择`、`停止测速`（仅运行中）、进度文案 `已完成 X/Y · 在测 N`。
- 空态：「还没有测速结果。选择节点后点击「下载速度」开始。」

### 8.4 右键菜单

- 在节点行上 `canvas.PointerOn(rowID)` 检测右键，`components.BeginContextMenu` 在指针处打开；`Viewport`/`DismissID` 负责点外与 Esc 关闭。
- 单层平铺，无子菜单。
- 单个节点语境：
  - `复制此节点信息`
  - `立即测试此节点`
  - `选中此节点` / `取消选中此节点`
  - `排除此节点`
- 已多选（右键落在某个已选节点上且选中数 > 1）语境：
  - `复制所选节点信息`
  - `立即测试所选节点`
  - `取消选中所选节点`
  - `排除所选节点`
- 复制用 `app.SetClipboardText`；文本含名称、条目、类型、服务器、上次测速、延迟、下载速度。
- 测速进行中 `立即测试…` 置灰。

### 8.5 测速编排

- 生产引擎复用 `internal/speedtester`：`New(Config)` + `SetProgressFunc` + `TestProxiesUntil(proxies, onStart, onResult)`。
- 传给引擎的 map key 用唯一键 `<entryID>/<nodeID>`；`Result.ProxyName` 即该 key，用于回填节点。
- 默认参数：下载模式（download）、下载 50MB、超时 5s、单节点并发 4、节点并行 6、服务器 URL 沿用旧默认。
- 后台 goroutine 只在测速期间存在；进度回调发布到互斥保护的 pending 队列后调用 `Invalidator.Invalidate()`；`OnWake` 在窗口线程把 pending 并入模型并重排。
- 每个结果立即持久化到 `results.json`（成功后更新 `tested_at`、`ok`）。
- 结束/停止后：运行标记归零，进度 goroutine 取消（引擎 `Stop` 取消 context），应用回到空闲，无重绘。
- `停止测速` 调 `Stop()`；已产出的结果保留。
- 同一时间只允许一轮测速；运行中禁用读取/重新获取/新建/删除条目，避免数据竞争。

## 10. Testing Decisions

测试只测外部可依赖行为，不测像素偏移与实现细节。

### 10.1 接缝（seam）

1. **GUI 应用（最高接缝）**：`gui.New(Options)` + `App.Config()` 交给 `app.Driver`；注入临时程序目录/数据目录与假引擎。覆盖条目 CRUD、路径对话框、自动/手动读取、分组、选择、过滤、预设、视图切换、实时排序、右键菜单、持久化、数据目录错误。
2. **store 包**：路径软硬转换、原子写、损坏 JSON、结果保留、跨重启读取。
3. **filter 包**：简化/高级语义、非法表达式、大小写、Unicode 通配、性能（无分配断言用 `testing.AllocsPerRun` 报告，不夸大）。
4. **headless 线协议**：`-tags vivahead` 构建 + `VIVA_HEADLESS=1`，用命令走查真实二进制（不是单测）。
5. 引擎不重测：保留 `internal/speedtester` 原有单测，新增 `LoadNodesFile` 测试。

### 10.2 Driver 测试用例清单（必须实现）

1. 条目新建：点 `新建条目` → 输入名称 → `选择文件…`（Driver `QueueOpenFiles`）→ 保存 → 条目出现、`entries.json` 落盘、路径为软路径。
2. 条目重命名 / 修改路径 / 删除（确认对话框）。
3. 勾选条目自动读取节点；`读取节点` 读取全部选中条目；两个条目同名节点各自成组、各自成行。
4. 「重新获取节点」：文件改为 A+B-C 后，A 保留上次测速时间文案与结果，B 显示「未测试」，C 消失。
5. 简化过滤：`香港 *IPLC !试用` 的可见节点；切「或」后结果变化；切高级正则 `^HK-\\d+$`；非法正则显示错误且不崩。
6. 预设：保存、应用（模式+表达式一起恢复）、重命名、覆盖、删除，重启后仍在。
7. 点 `下载速度`：切到结果视图；假引擎依次产生结果后行按速度降序；**收集节点行 Hit ID，重排前后一致**。
8. `排除上次失败`：持久化失败节点被取消勾选；开始测试时只把非失败节点交给假引擎。
9. 右键：单选菜单文案 `复制此节点信息`，多选菜单文案 `复制所选节点信息`；菜单无子菜单；复制写入剪贴板。
10. 数据目录不可写：打开应用显示明确错误对话框，后续改动不落盘，不写到其它位置。
11. 空闲：假引擎结束并应用 pending 后，`driver.Advance(1s)` 无待处理帧、`Transitioning()` 为 false。
12. store：软路径保存/迁移后仍可解析；硬路径保留；损坏 JSON 报错；结果跨重启保留。
13. filter：与/或/排除/通配/大小写/空表达式/非法正则。

### 10.3 headless 走查（必须执行）

- 构建 `-tags vivahead` 到临时目录，旁边放 `data/` 与 `a.yaml`、`b.yaml` 夹具。
- 命令序列覆盖：`texts` 看条目/分组、`click "读取节点"`、`type` 过滤词、`click "下载速度"`（假数据不可注入，走真实引擎会联网——因此走查只到「开始测速」前的界面与菜单，不真正联网；或者用仅含无效 server 的节点文件让测速快速失败但仍验证视图切换）。**不联网**：夹具节点使用 `127.0.0.1:1` 类地址，快速失败即可。
- `rightclick "节点 …"` 验证菜单文案、`click "复制此节点信息"`、`clip` 验证剪贴板。
- `openfiles` 排队系统文件对话框，验证新建条目。
- `layout` 无问题；`quit` 退出。
- 记录每条命令与 `ok/error` 结果。

### 10.4 未用真实窗口验证的项目（交付时明确列出）

IME、焦点丢失、真实键盘、高 DPI、窗口管理器关闭、真实 GPU 渲染外观、系统文件对话框真实交互。

### 10.5 完成前命令

```
gofmt -l .            # 必须无输出
go vet ./...          # 必须通过
go test ./... -count=1
```

## 11. Out of Scope

- 远程订阅 URL（本 GUI 只读本地文件条目）、Gist / GitHub 仓库上传、结果 PNG/TSV 导出、IP 归属地改名、延迟/速度阈值过滤、提前停止、多轮队列、暂停/继续、上传测速模式、主题切换、国际化、数据从旧 TUI/CLI 迁移（旧版没有持久化数据）、安装包/签名。
- 不用真实窗口验证的项目见 10.4。
